# X-Notepad

笔记与代码，一个窗口。Tauri 2 + CodeMirror 6 + WebAssembly 插件。

> 0.1.0 打底：编辑器、文件树、标签页、Markdown 分屏预览、编码安全读写跑通，
> 插件系统走 wasmtime 沙箱（ABI v1），示例插件是 CSV 查看器。
> 0.2.0 补齐文件树增删改、外部修改检测与崩溃恢复、WASM 插件市场。
> 0.3.0 补上会话恢复、命令面板（`Ctrl+P`）与 Markdown 大纲。
> 0.4.0 上全文搜索：SQLite FTS5 索引 + 中文按字切分，`Ctrl+Shift+F` 直接搜正文。
> 0.5.0 搜索结果按目录分组，加正则查找与全库替换，支持多窗口。
> 0.6.0 补上双链与反向链接，标签写进 front-matter（面板可增删，跟着文件走）。
> 0.7.0 改名时自动改掉全库引用，双链面板底部能一次看清所有断链。
> 0.8.0 上知识图谱：`Ctrl+Shift+G` 把全库双链摊成一张图，断链画成虚线空心点。

> 0.10.0 搜索结果每处命中各给一行上下文，点哪条跳哪条。
> 0.11.0 插件 ABI 升到 Component Model：WIT 描述接口，v1 核心模块继续能跑。
> 0.12.0 插件权限声明：`plugin.json` 列清要用的 host 能力，装之前先给你看。

## 为什么是这套栈

大纲原始方案是「Tauri + Scintilla（Rust 绑定）+ wasmtime」，落地时改了三处：

| 原方案 | 实际采用 | 原因 |
| --- | --- | --- |
| Scintilla（原生控件） | **CodeMirror 6** | Scintilla 只有 FFI 裸绑定（`scintilla-sys`，1.4 万下载、2025 年后停更），塞进 Tauri 窗口要给 Win32/Cocoa/GTK 各写一套挂载代码，React 那层 UI 还得给它让位。CM6 是视口渲染，语言包按需 `import()` |
| 启动 <0.3s、内存 <50MB | **<1s / <120MB（目标）** | WebView2 初始化本身就 300ms 起，50MB 只有自绘原生 UI 才做得到；这两个指标和 WebView 路线物理冲突 |
| 插件写成 TS 接口 + 同时支持 `.js` | **纯 WASM，ABI v2（组件）** | WebView 里跑的 `.js` 插件能拿到 `invoke`，沙箱形同虚设；统一成 wasm 后插件真的碰不到文件系统 |

Markdown 用 comrak（GFM：表格/任务列表/删除线/脚注/自动链接）在 Rust 侧解析，
前端只负责把 HTML 塞进 DOM，并且每次都过一遍 DOMPurify。

## 技术栈

- 外壳：Tauri 2（Rust）
- 前端：React 19 + TypeScript + Vite 8
- 编辑器：CodeMirror 6 + `@codemirror/language-data`（100+ 语言懒加载）
- Markdown：comrak 0.59（Rust）
- 编码：chardetng + encoding_rs（UTF-8 / GBK / Shift-JIS … 读进来什么样、存回去还什么样）
- 元数据：rusqlite（标签 / 收藏 / 最近打开）
- 插件：wasmtime 50（Component Model + v1 核心模块兼容层），接口用 WIT 描述
- 状态：zustand

## 写一个插件

插件是一个 **WebAssembly 组件**，接口由 [`wit/plugin.wit`](wit/plugin.wit) 描述：

```wit
world plugin {
  import host;                                  // log / now-ms / read-setting
  export api;                                   // parse / render
}
```

宿主把 `{action, path, content}` 交给 `render` 或 `parse`，插件返回 `response{ok, value, error}`。
字符串和记录由组件模型的规范 ABI 搬运，插件里没有指针、没有手写 JSON——沙箱里也依然只有
`host` 那三个函数，碰不到文件系统。完整约定见 [`docs/plugin-abi.md`](docs/plugin-abi.md)。

**能力要声明**。能看见 `host` 不等于能用：`plugin.json` 里写清要哪几个，宿主每个函数进来
先查清单，**默认一件都不给**。

```json
{ "abi": 2, "permissions": ["log", "read-setting"] }
```

| 能力 | 作用 | 被拒时 |
| --- | --- | --- |
| `log` | 打日志 | 这条日志丢掉 |
| `now-ms` | 取时间戳 | 拿到 `0` |
| `read-setting` | 读 `plugin-settings.json` | 拿到 `none` |

越权一次，整次运行就失败，报错直接写缺哪个能力——不糊弄成空结果。安装前也会提示：市场
条目带权限清单，本地 zip 走 `plugin_peek_zip` 只读包里的清单与 wasm 文件头，确认框里先
把「它将拿到什么」摆出来；索引和包对不上时，装完会明确告诉你「实际申请得更多」。
v1 老插件没这个字段，仍按历史行为给 `log` + `now-ms`，不会突然跑不了。

```bash
cd plugins/csv-viewer
./build.sh          # Windows: build.bat
# cargo build --target wasm32-unknown-unknown
# tools/wrap-component 把它包成组件（等价 wasm-tools component new）
```

用 Rust 写只需 `wit-bindgen`：

```rust
wit_bindgen::generate!({ path: "../../wit/plugin.wit", world: "plugin" });
```

不想用 Rust 也行：任何能产出组件的语言（`cargo component` / `jco` / TinyGo）都能写。
老的核心 wasm 插件（`alloc` / `run` / `result_len`，ABI v1）不用重写——宿主按 wasm
文件头自动分流，两代插件可以同时装着。

产物 `plugin.wasm` 与 `plugin.json` 放在同一个目录，把这个目录整体放进：

```
%APPDATA%\pw.lovou.xnotepad\plugins\<插件名>\
```

重启应用，工具栏「插件」里就能看到并直接对当前文件运行。

### 会话恢复

正常退出后再打开，会回到上次的文件夹、还开着的标签、以及每个文件的光标位置——
这些记在 `localStorage`（`xnp:session:v1`），不占数据库。目录被移走或删掉时就当没有会话，
老老实实显示欢迎页；单个文件没了只跳过那一个标签。
光标跟着改名走（目录改名做前缀映射），关掉的标签连同光标一起清，不会越攒越多。

### 全文搜索

索引存在应用数据目录的 `x-notepad-search.db`（SQLite FTS5），跟元数据库分开——重建索引是
「整表重灌」的量级，不该和标签 / 收藏抢同一把锁。打开工作区后在后台建一次，之后保存、
外部修改、改名、删除都会增量更新。

中文得自己切：FTS5 的 `unicode61` 会把一整串汉字当成一个 token，所以建索引和拼查询时都把
汉字逐字空格隔开，查询侧用短语（`"笔 记"*`）——这样「笔记」能命中「笔记本」，「note」也能
按前缀命中 notebook。摘要与行号由 Rust 从原文里算，前端只负责把 `<mark>` 画出来。

#### 每处命中各一行上下文

搜索结果不再只给每个文件一段摘要——文件名下面按行列出**每一处命中所在的整行**：

- 左边是行号，右边是那一行的原文（缩进已去掉，命中处高亮），点哪条就跳到哪一行哪一列。
- 同一行里命中几次只占一条，那一条里几处一起标出来（`matches` 记次数，`spanTotal` 记行数）。
- 每个文件最多带 20 行（再多也没人一行行看），超出的在下面提示「还有 N 行没列出」。
- 超长行会截：压缩过的 JS / JSON 一行能有几十万字符，原样塞进结果就是几十兆的 payload，
  所以一行最多带 240 字符、命中处前留 60 字符，两端补「…」。
- 折行逻辑是纯函数（`src-tauri/src/lines.rs` 的 `group`，前端 `lib/search.ts` 的 `spansOf`
  一一对应）：文本 + 绝对区间进，行窗口出。跨行命中在本行截断，CRLF 的 `\r` 不算进上下文。

浏览器演示模式没有后端，就在内存里扫一遍示例文件，行为对齐，方便只跑前端调 UI。

命中结果按所在目录分组（组头显示「N 个文件 · M 处」，点一下折叠），组之间沿用相关度顺序，
所以同一个目录的命中不会被别的目录隔开。

### 正则与全库替换

搜索框右边的 **Aa** 管大小写，**.\*** 切正则，**⇄** 展开替换行。

- 正则模式**不走 FTS5**：`docs` 表里存着全文，直接在正文上跑 `regex`（线性时间，不会灾难性回溯），
  文件名 / 路径命中也算。正则语法按 Rust `regex` 来：支持 `(分组)`、`$1` 引用、`(?i)` 内联开关，
  不支持反向引用与 lookaround。
- 「全部替换」分两步：先 `dryRun` 扫一遍，把「将在 N 个文件里替换 M 处」和文件清单摆给你看，
  确认后才落盘；替换时保留各文件原来的编码与换行符，替换完立刻重灌该文件的索引。
- 磁盘替换只动**没有未保存修改**的文件：先自动保存一遍，仍有改动（保存失败 / 只读）的文件会被
  跳过并在报告里点名，免得替换结果被下一次自动保存盖回去。

### 撤销全库替换

替换是少数「一按就改几十个文件」的操作，所以它先留底再动手：

- 每动一个文件之前，把它**替换前的原始字节**和**替换后写下的字节**一起存进快照目录
  （`<数据目录>/replace-snapshots/<时间戳>/`，`0.before` / `0.after` + 一份 `manifest.json`）。
  存字节而不是解码后的文本，撤销时能一字不差写回去：GBK 文件、BOM、CRLF 都不会越撤越歪。
- 替换完成，替换行里多出一个**撤销**按钮（命令面板里也有「撤销上次全库替换」），点一下按原字节写回。
- 撤销前逐个比对：盘上的内容**还是替换后那份**才覆盖。替换完又手改过的文件跳过并说明原因，
  删掉的文件也不会被凭空造回来——半截撤销比不撤销更糟。
- 快照只留最近 20 份，撤完一份就删一份，所以连按两次「撤销」会一路退回更早的替换。
  撤销按钮只认当前这一轮，重启后按钮没了，但命令面板的撤销仍能撤最近一次（快照在磁盘上）。
- 实现在 `src-tauri/src/snapshot.rs`（写 / 读 / 清理快照）+ `replace_plan.rs`（判断哪些文件能安全恢复，
  纯函数、不碰磁盘，出错代价最高的一块单独测）。

### 多窗口

`Ctrl+Alt+N` 或工具栏「⧉ 新窗口」开一个新窗口，命令面板里还能「在新窗口打开当前文件」。
每个窗口是独立的 JS 上下文：工作区、标签、大纲开关各管各的。

- 文件监听按窗口隔离（`AppState.watchers` 以 label 为 key），A 窗口换工作区不会把 B 的监听顶掉，
  事件用 `emit_to` 只推给对应的窗口。
- 会话按窗口分仓：主窗口继续用 `xnp:session:v1`（升级不丢），新窗口用 `xnp:session:v1:win-1`。
  从别的窗口带 `?root=…&file=…` 打开的那一次，直接进目标工作区，不读本窗口的旧会话。

### 双链与标签

笔记之间用 `[[想法]]` 互相指，左侧「双链」页签列出**谁引用了我**（反链）和**我引用了谁**（出链）。

- 三种写法都认：`[[想法]]`、`[[想法|显示成这个]]`、`[[notes/想法#小节]]`；指向本地 `.md` 的普通
  Markdown 链接（`[文字](notes/a.md)`）也算引用。代码块和行内代码里的 `[[...]]` 不算——
  写文档时经常要举例子。
- 解析顺序是「文件名 → 标题 → 路径后缀」，所以 `[[想法]]` 能命中 `notes/想法.md`，
  `[[想法池]]` 也能命中标题叫「想法池」的笔记。
- 出链指向不存在的笔记时显示成虚线，点一下问你要不要就地新建 —— 先写链接、之后再补内容。
- 预览里的双链也能点。渲染前把 `[[x]]` 换成 `#xnp-wiki:` 锚点，所以不用给 comrak 开原始 HTML。
- 图从全文索引的正文里扫（不重复读磁盘），几百篇毫秒级；**当前打开的那篇用缓冲区内容**，
  刚敲下的 `[[新笔记]]` 立刻出现在面板里，不用等保存。

链子会不会断，是双链体系能不能长期用下去的关键，所以补了两处：

- **改名自动改引用**：把 `想法.md` 改成 `笔记.md` 时，先扫出全库指向它的链接，
  弹一次「有 N 个文件共 M 处链接指向想法，一起改吗？」——选「一起改」就把
  `[[想法]]`→`[[笔记]]`、`[[想法|我的想法]]`→`[[笔记|我的想法]]`（别名是作者写的，不动）、
  `[文字](notes/想法.md)` 都换掉，目录前缀和 `#小节` 锚点原样保留。选「只改名」就只动文件名。
  方案在**改名之前**算：改完名 `[[旧名]]` 就解析不到任何文件了。
- **断链体检**：双链面板底部常驻「断链 N」，点 ＋ 展开列出全库指不到文件的链接
  （文件名 + 行号），点一条跳到出处那一行去修。删文件、改错名字留下的坑，一次就能看全。

标签有两个来源：front-matter 的 `tags`（`[a, b]`、`a, b`、`- a` 三种写法都认）和正文里的 `#标签`。

- 面板里增删的是 **front-matter**，正文的 `#标签` 只读（那属于原文，要删去正文删），界面上用虚线框区分。
- 写回保留文件原有编码与换行；如果这篇正文还有未保存的改动，标签改动只进缓冲区，
  跟 1.2 秒后的自动保存一起落盘——否则「写标签」会把正在编辑的正文档回磁盘版本。
- 「全部标签」按出现次数排序，点一个就地筛出带它的文件。

### 知识图谱

`Ctrl+Shift+G`（或工具栏「图谱」）把全库双链摊成一张全屏的图，看的是**结构**，不是某一篇：

- 圆点是笔记、连线是引用；点越大说明引用越多（被引 + 引用别人），标签跟着点走。
- 颜色按目录分，同一个目录永远同一个颜色，左下角有图例。
- 指不到任何文件的双链画成**虚线空心点**（图例里的「未创建」），点一下问你要不要就地新建——
  「待写清单」直接长在图上。指向自己的链接不画，只记一笔数。
- 搜索框按文件名 / 标题 / 标签筛，不相关的点变淡；「孤立」只看没有任何链接进出的笔记；
  「断链」开关收起空心点，只看已经存在的笔记。
- 拖动空白处平移，滚轮以指针为中心缩放，圆点可以拖着摆位置（位置只活在这个窗口里，不落盘）。
- 点圆点打开那篇笔记并关掉浮层——图是用来找路的。

布局是固定种子的力导向，纯前端算：同样的笔记每次打开都是同一张图，不会「跳一下」；
缠在一起点「重排」换一套初始摆位。实现在 `src/lib/forcegraph.ts`，不碰 DOM，
所以 `buildGraph` / `layoutGraph` 这两块能在 jsdom 里直接断言（去重、权重、幽灵节点、
坐标有限且在画布内、确定性）。

### 外部修改与崩溃恢复

- **外部修改**：工作区开着 `notify` 监听。别的程序（或同步盘）改了当前打开的文件时，
  编辑器上方会出现提示条，让你选择「重新载入」还是「保留我的修改」——绝不悄悄覆盖。
  自己保存触发的写入会被 1.5 秒的自写窗口过滤掉。
- **崩溃恢复**：编辑时每 0.6 秒把缓冲区写一份到 localStorage（最多 3MB，超过丢最旧的）。
  如果进程被强杀，下次启动会问要不要把这几篇未保存的内容捡回来。
