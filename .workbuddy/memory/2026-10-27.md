## 读《X-Notepad 0.1.0 开发大纲》的可行性结论（尚未开工）

大纲：Tauri 2 + React/TS + Scintilla(Rust 绑定) + comrak + rusqlite + wasmtime 插件；
硬指标 启动 <0.3s / 内存 <50MB / 三平台；9 周出 0.1.0。

**核实到的外部事实**
- `scintilla-sys` 仅 5.5.7、14,180 次下载、2025-04 后未更新；crates.io 上**没有** `scintilla` 高层封装 crate
- Tauri 2 的 child/parent 只作用于 webview，嵌入原生控件要靠 HWND/NSView/GTK 手写，且 issue #10079 显示多平台行为不统一
- 成熟依赖：comrak 0.59（9.5M 下载 / 2026-10 更新）、rusqlite 0.41（136M）、chardetng 1.0（16.5M）、syntect 5.3（35M）
- WebView 路线实测量级：冷启动 0.4–1.2s、空载 100–150MB（vs Electron 300–400MB）

**三处硬冲突（必须先改判，否则 0.1.0 做不出来）**
1. Scintilla ↔ React/Tauri 抢同一块窗口，且三平台要三套原生代码 → 建议 CodeMirror 6 / Monaco
2. 启动 <0.3s、内存 <50MB 与「WebView + React」物理冲突 → 要么放宽到 <1.2s / <150MB，要么整体换原生（egui/iced/Qt）
3. 插件规范写成 TS（`export const pluginName`）却要跑 WASM；4.2 又允许 `.js` 插件（在 WebView 里等于没有沙箱）→ 二选一

**其他待修**
- 「Shadcn/ui 或 Naive UI」不成立：Naive UI 是 Vue 3 的，React 下只能 shadcn/ui 或 Ant Design
- 9 周排期把三个高风险项塞进 0.1.0，单人不可行；建议 0.1.0 砍到 MVP、插件只做 index.json 安装、WASM 推到 0.2
- SQLite 元数据 + 文件正文双写需处理外部改动（notify）与重命名后的 id 迁移
- 插件市场可复用 X-Note 已跑通的 `index.json + zip + jsDelivr/Gitee 双源` 模式，省 1–2 周
